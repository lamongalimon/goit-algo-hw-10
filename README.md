Жадібний алгоритм vs динамічне програмування

Монети: [50, 25, 10, 5, 2, 1]. Для суми 113 обидві функції повертають {50: 2, 10: 1, 2: 1, 1: 1}.

Складність
Алгоритм	Час	Пам'ять
Жадібний	O(k), k — кількість номіналів; від суми не залежить	O(k)
ДП	O(amount · k)	O(amount)
Час виконання (секунди)
Сума	     Жадібний	  ДП
113	       0.0000002	  0.000036
10 000	   0.0000002	  0.002816
1 000 000	 0.0000002	0.273634

Час жадібного алгоритму не змінюється, час ДП зростає лінійно із сумою.

Висновки
Для стандартного набору монет жадібний алгоритм дає оптимальний результат і працює миттєво для будь-якої суми — найкращий вибір для каси.
ДП гарантує мінімум для будь-якого набору монет. Наприклад, для [4, 3, 1] і суми 6 жадібний дає 3 монети (4+1+1), а ДП — 2 (3+3). Ціна — повільна робота й велика витрата пам'яті на великих сумах.
